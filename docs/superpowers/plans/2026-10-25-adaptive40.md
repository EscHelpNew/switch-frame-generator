# Adaptive40 and profiling Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline. User requested direct implementation in the existing preview.

**Goal:** Add stable 40-Hz presentation for a separately timed 20–30-FPS source, at most one generated frame per source, with a measured resource report.
**Architecture:** A pure timestamp planner maps source pairs onto a 25-ms output grid; the last slot receives the current real image and at most one earlier slot receives LSFG at the correct fractional timestamp. A bounded GPU image queue adds 75 ms of lookahead. Input is polled between outputs; a jump discards stale queued images and schedules an immediate real response, with repeats during history recovery explicitly counted.
**Tech Stack:** Existing OpenGL4.5 preview, shared LSFG graph and GLSL, Win32 process CPU/RSS accounting, GPU timestamp queries, Python report aggregation.
**Spec:** Latest user instructions override the earlier target60/two-generated proposal: target40, cap1generated, source20–30, native1280x720, no Switch deployment.

## Global Constraints

- No increase to the one-generated-per-source cap; below20FPS may need repetitions, never label those generated.
- Distinguish source frames, generated shown, generated computed, repeated output, late output and GPU elapsed time.
- Preserve existing fixed30/LSFG2x/native60 modes and click/toggle controls.
- Source cadence must not be driven by the number of presents.
- GPU memory is bounded; no unbounded queued latency; release old preview gracefully before rebuilding.
