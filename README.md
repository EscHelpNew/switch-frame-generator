# Switch Frame Generator

Экспериментальный LSFG 2x-стенд для **первой Nintendo Switch**: мяч падает на пол
и отскакивает. Рендер и вывод — **1280×720**, без уменьшения разрешения.
Можно сравнить обычные 30 FPS, LSFG 30→60 и настоящие 60 FPS.

Основа — существующий LSFG/deko3d из DrasticDS_nx. Для сборки нужна собственная
`Lossless.dll`. Шейдеры подготавливаются на ПК и упаковываются в локальный NRO;
DLL на Switch не запускается. Демо проверено на реальной консоли через netloader:
LSFG при 720p занял около 4,9 мс GPU. Подробности и ограничения — в
[отчёте первого запуска](docs/SWITCH_FIRST_RUN_RU.md).

[Результаты проверок](docs/VALIDATION.md) · [Лицензии и происхождение](THIRD_PARTY.md)

## Демонстрация на ПК

```powershell
py -3 build.py --host-only
.\run-desktop.ps1
```

Или запустите `run-desktop.cmd` после сборки. Откроется окно **1280×720**.
Нужен GPU с OpenGL 4.5 или новее. На ПК исполняются настоящие compute-шейдеры
LSFG из той же цепочки GLSL/схемы ресурсов; Tegra DKSH используется только на Switch.

- Кнопка **«Генератор: ВКЛ / ВЫКЛ»** или **G** включает/отключает LSFG;
  в фиксированном режиме это сравнение с обычными 30 FPS.
- **«20–30 → 40»** или **V** — отдельный адаптивный режим. Источник меняется
  от 20 до 30 FPS; цель вывода 40 FPS, максимум один промежуточный кадр на реальный.
  Здесь G сравнивает FG с отключённой генерацией на том же переменном источнике.
- Включённые кнопки подсвечены ярким бирюзовым цветом, выключенные приглушены.
- Пауза и замедление доступны отдельными кнопками с такими же индикаторами.
- Щелчок по мячу заставляет его подпрыгнуть.
- **A** переключает все три режима, включая native 60 FPS.
- **X** — сброс, **B/Space** — пауза, **Y** — замедление, **Esc** — выход.

Журнал: `build/desktop.log`. Приложение ограничивает вывод 60 вызовами SwapBuffers
в секунду в исходных режимах и 40 в адаптивном; монитор и оконный композитор могут влиять на реальный показ.
Скорость ПК не переносится на Switch.

По умолчанию открывается адаптивный режим. Для фиксированного сравнения:
`.\run-desktop.ps1 -Mode lsfg`. Подробный измеренный отчёт:
**[PERFORMANCE_RU.md](docs/PERFORMANCE_RU.md)**. Сырые CSV и JSON находятся в `build/perf-*`.

```powershell
.\tools\benchmark.ps1 -Seconds 14  # закрыть интерактивное окно перед замером
py -3 tools/report_performance.py
py -3 tests/adaptive_check.py
```

Короткий GPU-тест трёх режимов: `.\run-desktop.ps1 -Smoke`. Он завершается после
360 исходных кадров. Для автоматической проверки лога и собственного framebuffer
после этого запуска: `py -3 tests/desktop_check.py`.

## Сборка на Windows

Нужны native Windows Python 3.11+, native CMake 3.22+, MSYS2 UCRT64 GCC,
MSYS bison/flex, установленный devkitPro с devkitA64, libnx, deko3d и switch-tools.
Сборка использует существующий SDK в `C:/msys64/opt/devkitpro` либо `DEVKITPRO`.

Положите свою `Lossless.dll` в корень и выполните:

```powershell
py -3 build.py
```

Первый запуск скачает закреплённые исходники SPIRV-Cross/UAM и небольшие
host-зависимости в `build/`; глобальная установка Python-пакетов не выполняется.
Обычный MSYS `/usr/bin/python` не подходит: используйте native Windows Python.
При необходимости задайте `SFG_MSYS_ROOT`, `SFG_CMAKE` или полный путь к Python.

Результат: `build/switch-frame-generator.nro`. Метаданные и SHA-256:
`build/build.json`. `build/`, DLL и shader caches исключены из Git.

```powershell
py -3 build.py --test         # полная сборка и реальные host-проверки шейдеров
py -3 build.py --target-only  # пересобрать NRO с уже подготовленным кэшем
py -3 build.py --host-only    # только подготовка и проверка на ПК
```

## Запуск через netloader

Когда будете готовы к проверке: откройте hbmenu в **application mode**,
нажмите **Y**, затем на ПК:

```powershell
.\run.ps1 -Address 192.168.1.131
.\run.ps1 -Address 192.168.1.131 -Mode lsfg -Frames 300
.\run.ps1 -Address 192.168.1.131 -ReuseLogServer # если приёмник TCP28771 уже работает
```

Замените пример IP адресом своей консоли. Без `-Address` скрипт читает `Ip`
из `../switch-monitor/data/config.json`, если этот локальный файл существует.
`-Frames 300` завершает демо после 300 исходных кадров; без ограничения оно
работает до выхода. Скрипт передаёт NRO в `sdmc:/switch/switch-frame-generator.nro`
и принимает nxlink-журнал в текущем терминале.

| Кнопка | Действие |
| --- | --- |
| A | 30 FPS → LSFG 30→60 → native 60 FPS |
| X | Сброс мяча и истории LSFG |
| B | Пауза |
| Y | Замедленное движение |
| + | Выход |

При отсутствии/ошибке кэша базовые режимы остаются доступны; причина ошибки
выводится в журнал и HUD. В LSFG используется Performance, flow 1/4, high precision.
Счётчик `PRESENT CALLS` показывает вызовы present, а не подтверждённые scanout.
Генерация использует ресурсы того же GPU: 60 показов/с заранее не гарантируются.

## Использование в игре

Публичный адаптер — `include/sfg/generator.hpp` и `source/generator.cpp`.
Он принимает готовые изображения: глубина и motion vectors не требуются.
Необходимы доступ к color target и управление presentation. Пошаговое подключение,
исходники для линковки, fences, HUD и порядок кадров описаны в
[INTEGRATION_RU.md](docs/INTEGRATION_RU.md).

Это не универсальный системный перехватчик изображения готовых игр.
Подобный режим требует отдельной интеграции с очередями NVN/EGL/Vulkan.
